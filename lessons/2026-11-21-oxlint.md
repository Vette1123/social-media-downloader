# ESLint to oxlint, 2026-11-21

## What

- `pnpm lint` is `oxlint --report-unused-disable-directives --deny-warnings`: 2.3 s for 467 files
  against ESLint's 14.6 s. `eslint`, `eslint-config-next`, `eslint.config.mjs` and the eslint-only
  `minimatch` override are gone.
- `.oxlintrc.json` keeps every rule eslint-config-next enforced (nextjs, react, React Compiler
  hooks rules, jsx-a11y, typescript) and adds the whole `correctness` category plus type-aware rules
  through `oxlint-tsgolint`, which runs on TypeScript 7.
- What the new rules found and fixed: 6 un-voided `handleProcess` promises, `http.head`/`http.get`
  passed unbound, `mediaProxy` `json()` spreading a `HeadersInit` (a `Headers` instance or pairs
  array would drop every header; the type now takes a record only), two `unknown | null` unions,
  no-op escapes in test fixtures, and four script nits.
- TS 6 stays installed as `typescript`: `next build`'s in-process check and `scripts/i18n-deep.mjs`
  use the JS compiler API, which TS 7 does not ship. The linter no longer needs it.

## Mistakes

- `@oxlint/migrate` wrote `"correctness": "off"` and ~1,000 inlined browser globals. Taken as-is,
  oxlint would have run fewer bug rules than its own defaults. Rewrote the config by hand with
  `env.browser`.
- The first probe also turned on `suspicious`: 387 hits, 201 of them `no-unsafe-type-assertion`.
  That is noise. `correctness` alone came to 121, every one either fixed or switched off with a reason.

## What worked

- Probing with a throwaway config (`-c`, `--format=json`, counted by rule) before choosing rules.
- A red check on the rule itself: dropping one `void` makes `pnpm lint` fail on
  `no-floating-promises`.

## Rules

- After any lint migration tool, read the categories it set. Off-by-default is not parity.
- The five jsx-a11y rules switched off (32 hits) are a UI pass of their own. Turn each one on as its hits are fixed.
