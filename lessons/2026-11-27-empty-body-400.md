# Empty POST body answered 400, not 500

## What
PostHog `01a1d386` ("WorkerResponse: [/api/download]") reopened with 2 events at 06:58 on
27 Nov. The 14 Nov fix (5xx reports carry the body's reason) worked: the title now read
"Unexpected end of JSON input". A no-UA client had POSTed an empty body; `request.json()`
threw a SyntaxError, the handler's catch passed it to `resolveFailure`, and a SyntaxError is
not a base `Error`, so it got 500. A `null` body was a TypeError, also 500. The fix is
`readJsonObject` in `src/lib/apiRoutes.ts`: one guard returns 400 for download, playlist,
subtitles and images (`da72bb2`). The issue is resolved and in `scripts/posthog-fixed.json`.

## Mistakes
- The tier-2 sweep agent read the issue as "1 event, last seen 13 Nov, stale". `posthog:issues`
  run directly showed today's 2 events and the new title. Re-read the board yourself before
  calling an issue stale.
- The first fix only went into `handleDownload`. A grep for `request.json()` found the same
  unguarded parse in 3 more handlers.

## What worked
- Making 5xx reports carry the reason paid off: the next occurrence named its own cause.
- The test runs `['', 'not json', 'null', '[]']` against both handlers that skip the Pro gate.

## Rules
- A body the caller sent wrong is a 400 at parse time. It must never reach the catch-all.
