# A supporter grant that ends by itself

## What

GitHub Sponsors became the way to support (tiers: $5/month, $50 one-time "one
year", $99 one-time "lifetime"). GitHub has no yearly billing, so the $50 tier
is a prepaid year, and `pnpm pro` could only grant forever. Added
`pnpm pro <email> --until YYYY-MM-DD|1y`:

- `migrations/0009_pro_until.sql`: `users.pro_until`, `supporters.ends_at`,
  both nullable epoch ms, null meaning forever. Applied to prod by hand
  (`pragma_table_info` first) before the code shipped.
- `isEntitled` reads the `pro` grant as valid only before `pro_until`.
- `claimSupporterGrants` copies `ends_at` onto the account at sign-in.
- `scripts/pro-until.mjs` parses and validates the flag. A typo throws instead
  of granting forever or ending today.

## Mistakes

- First instinct was to reuse the Creem columns: `sub_status = 'canceled'` plus
  `sub_ends_at` already expires on its own in `isProAt`. That would have
  labelled every one-year supporter "Cancelled" on the account card and handed
  the row to the Creem reconcile path. The grant got its own date instead.
- Inlined the `--until` argument parsing as a nested ternary, which is banned
  here. Moved it into `splitUntil` with its own test.
- The sponsor tiers first went up naming this project. The owner wants them
  generic and reusable across apps, so they say "supporter perks in my apps".
  Ask how public the wording should be before publishing anything.

## What worked

Tests first at each seam: `isEntitled` (date in future / past / exact / null),
`claimSupporterGrants` against a three-statement fake D1, and the parser. Each
was seen red before the change.

## Rules

- A time-limited grant is `pnpm pro <email> --until 1y`. A plain grant makes
  the address lifetime and clears any date; `--revoke` clears both.
- `pro_until` bounds only the `pro` grant. A paid subscription (`isProAt`) and
  the `ig` flag are untouched by it.
- Schema ahead of code, as always: `session.ts` selects `users.pro_until` on
  every request, so shipping it before the column exists breaks every sign-in.
